# Disaster province pick: all 256 random indices and SAME-MONTH province coherence

Generated by `tools/analyze_disaster_pick_rng.py` (`make disasterrng`) from `rom/prg/prg_1f.bin` + `asm/banks/prg_1f.asm` (RNG), `asm/banks/prg_19_1a.asm` (`ProvincePickListBuild` $A896, pools $A8C0/$A8D0) and `docs/province_names.csv`.

CSV twins: [`disaster_pick_rng_sequences.csv`](../docs/disaster_pick_rng_sequences.csv) (256 indices), [`disaster_pick_rng_pair_coherence.csv`](../docs/disaster_pick_rng_pair_coherence.csv) (all 105 province pairs x 2 pools x 2 models).

## Scope: why there is no cross-month coherence

`$0050` is the **single global** RNG index shared by every `B1F_RandomByte` caller (`RandomByte2/3/4` use independent indices $0052/$0054/$0055). Between two disaster months a strategy turn burns a large, data-dependent amount of it — AI action rolls, advice rolls, map scrolls, battle and duel code all call the same walk — so the index a disaster month starts on is **not** a function of the previous disaster month's index. Any 'stride'/'cycle' coupling between months is an artefact of ignoring those consumers, so it is not analysed here.
What remains, and what this report measures, is coherence **inside one month**: the 16 slot rolls of one month are drawn from one contiguous stretch of the same 256-entry table, so the hit indicators of two Provinces are not independent — that coupling is the 210 entries of the pair-coherence CSV.

## Sample space and models

The random index at loop entry can be any of 0..255, so there are exactly **256 cases**, one per index, and each case yields one 16-value mod8 sequence. Two readings are computed:

| model | definition | table entries eaten per month |
|---|---|---|
| **W** plain window | the 16 consecutive entries at the index, each `& $07` (the literal '16 calls' reading) | exactly 16 |
| **R** ROM | the actual loop: re-roll `RandomMod8` while `>= $06`, keep slot only on `$00` ($A8A5-$A8AA) | 17..27 (mean 21.30) |

**Uniqueness check (requested):** model W yields 256 distinct 16-digit sequences out of 256 indices (0 duplicates) — every index does generate its own sequence, as expected. Model R yields 192 distinct sequences (64 duplicates): an index whose own byte is a re-roll byte (`& $07 >= $06`, 64 of 256 entries) eats that byte before the first slot and therefore produces *exactly* the accepted sequence of index+1, so runs of consecutive re-roll bytes collapse onto one outcome.
The 192 distinct R sequences are **not equiprobable**: sequence multiplicity = 1 + length of the re-roll run immediately preceding its index (predicted multiplicities verified against the observed counts): weight 1: 145 sequence(s), weight 2: 36 sequence(s), weight 3: 6 sequence(s), weight 4: 4 sequence(s), weight 5: 1 sequence(s). All statistics in this report are therefore computed over the 256 *indices* (the uniform sample space the hardware walks), not over the 192 distinct strings — counting indices automatically carries the right weights.

Consequence for the plain '16 calls' intuition: model W's per-slot hit share is 32/256 = **1/8** (mean 2.000 hits/month), while the ROM's rejection sampling renormalises it to 32/192 = **1/6** (mean 2.660). The re-rolls are what raise the disaster rate by a third.

Model R's sequence for index *i+1* is usually model R's sequence for *i* shifted by one digit with a new tail digit, because the accepted-value stream is the same table walk minus the rejected bytes; that is a property of the enumeration, not extra randomness.

## 1. The random table ($E8BA, 256 bytes)

```
byte & $07 histogram: 0:32  1:32  2:32  3:32  4:32  5:32  6:32  7:32
accepted (<$06): 192 bytes -> per-slot hit share 32/192 = 0.1667
re-rolled (>= $06): 64 bytes = 25.0% of the table
```

The table is perfectly balanced (32 of each low-nibble value), so the marginal hit chance of one slot is exactly 1/6 = 16.67%; all deviation in this report is therefore joint-structure, not per-slot bias.

## 4. SAME-MONTH coherence between two Provinces

For each pair of slots (a, b) over the 256 indices: `n11` = indices where both Provinces are hit, `E` = `n_a x n_b / 256` (independence), `lift = n11 / E`, `phi` = the Pearson correlation of the two hit indicators (+1 = always together, -1 = mutually exclusive, 0 = independent). 105 pairs per pool, 420 rows in the CSV.

```
model R  lift: min 0.116  median 0.726  max 1.939   phi: min -0.199  max +0.190
model W  lift: min 0.500  median 0.750  max 1.750   phi: min -0.071  max +0.107
```
So within one month the joint risk is *not* the product of the marginals: model R pairs range 12%..194% of independence, model W pairs 50%..175%. Because slot -> Province is positional, these are literally Province pairs.

The **net** coupling is repulsion: mean lift over the 105 Province pairs 0.801, mean phi -0.0397. That is forced by the hit-count budget of section 3 — a:$0000 counts all 16 slots, its variance is 0.951 against a sum of independent per-slot variances of 2.216, and the 1.265 deficit has to be carried by the 2 x 120 covariances (mean covariance -0.00527). In plain terms: a month holds roughly 2-3 hits and the table spreads them out, so knowing one Province was hit makes another one *less* likely to be hit than chance would suggest.

Model W's coupling is a pure function of the slot *distance* (all pairs at the same distance come out identical, since the two slots just read table entries *d* apart); model R breaks that degeneracy because each re-roll shifts the following slots by a variable amount.

### 4.2 Mechanism: the coherence is the table's own autocorrelation

In model W a Province pair at slot distance *d* is hit together exactly when two table entries *d* apart both satisfy `& $07 == 0`. So the joint count is the lag-*d* autocorrelation `C(d)` of the 32 hit-byte positions, and independence predicts `C = 256 x (32/256)^2 = 4.0`. Measured directly from `$E8BA`:

|---|---|---|---|---|---|
| 1 | 2 | 0.500 | 0.500 | 17 | 1.062 |
| 2 | 3 | 0.750 | 0.750 | 16 | 1.000 |
| 3 | 2 | 0.500 | 0.500 | 13 | 0.812 |
| 4 | 3 | 0.750 | 0.750 | 17 | 1.062 |
| 5 | 2 | 0.500 | 0.500 | 19 | 1.188 |
| 6 | 5 | 1.250 | 1.250 | 13 | 0.812 |
| 7 | 3 | 0.750 | 0.750 | 14 | 0.875 |
| 8 | 3 | 0.750 | 0.750 | 14 | 0.875 |
| 9 | 3 | 0.750 | 0.750 | 18 | 1.125 |
| 10 | 7 | 1.750 | 1.750 | 16 | 1.000 |
| 11 | 3 | 0.750 | 0.750 | 17 | 1.062 |
| 12 | 6 | 1.500 | 1.500 | 19 | 1.188 |
| 13 | 2 | 0.500 | 0.500 | 18 | 1.125 |
| 14 | 5 | 1.250 | 1.250 | 18 | 1.125 |
| 15 | 2 | 0.500 | n/a (slot 15 is the $FF tail) | 14 | 0.875 |

Every W lift equals `C(d)/4.0` exactly, which proves the coupling is not a property of the Provinces or of the pick algorithm but of **where Namco put the zeros in the 256-byte table** (the `32` entries with `& $07 == 0`, whose lag-*d* autocorrelations are listed above).

Model R does **not** preserve that clean profile: because each re-roll shifts every following slot by a variable amount, a slot pair at distance *d* samples a spread of table lags instead of one. That is why R's per-distance means (0.19..1.64) diverge from W's `C(d)/4.0` (0.50..1.75) and why individual R pairs at the same distance differ from each other (R lift 0.12..1.94) while W pairs at a fixed distance are identical. W is the diagnostic, R is what the console does.

Practical reading: the R pairs at distance 1/3/4 are the near-impossible ones (down to 1 of 256 indices where independence predicts 8.6), while distance 5/7/9 pairs co-occur up to 1.94x as often as chance. Which Provinces those are follows from the pool tables ($A8C0/$A8D0) — slot distance is not map distance, so the coupled pairs are effectively arbitrary Province combinations, listed by name in section 4.3.

### 4.4 Flood Province vs drought Province: mutually exclusive

A drought Province id and a flood Province id can never co-occur in one month: the pools are disjoint halves of the 30 Province ids, so the same-month joint count for any flood+drought pair is **45** (out of 256 indices, 105 real pairs each) and `lift = 0`, `phi = -1`. This is structural (data layout), not probabilistic — the strongest coherence in the system, and the reason a Province never sees both 洪水 and 日照り.

## 6. Caveats

* Model R is the ROM-faithful replay (verified byte-for-byte against $A8A5-$A8BD); model W is the analytical '16 independent-looking calls' simplification. Where they disagree, R is what the console does.
* The 256 indices are treated as equally likely. In a real save the index distribution is set by unrelated RNG traffic, which is also what destroys cross-month coupling.
* `@DamageProvincePoll` / `@LossProvincePoll` still skip an UnclaimedLand Province (owner nibble 7) and an AI/unattended country (`Country[$03]==$03`), so a *rendered* pair of hits can be smaller than the list built here; the joint statistics above are about the built list.
* Damage severity is a separate roll (`DisasterSeverityRoll`, 防災 tiered) and does not feed back into which Provinces are in the list.
